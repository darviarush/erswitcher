# Методология тестирования

> Функциональные тесты, динамический анализ (санитайзеры) и фаззинг-тесты
> Добавить нагрузочные тесты

1. Как тестировать статические буферы (Предотвращение Buffer Overflow)

Статические кольцевые буферы (например, char buffer[256]) — это отличный выбор для Си-утилит, так как они выделяются в памяти один раз и не требуют malloc. Но их нужно проверять на граничные условия (Boundary Conditions).
• Функциональные тесты (в Criterion): Напишите тесты, которые целенаправленно забивают буфер до предела и пытаются выйти за его рамки.
	• Тест 1: Набрать слово длиной ровно в размер буфера. Проверить, что код не упал, а последний символ записался корректно.
	• Тест 2: Набрать слово, превышающее размер буфера в 2 раза. Убедиться, что буфер либо циклично перезаписался, либо заигнорировал лишние символы (в зависимости от вашей логики), но строка осталась валидно нуль-терминированной (\0).
• Инструментальный контроль: Запускайте эти тесты под ASan (AddressSanitizer). Как только код попытается записать байт по индексу buffer[256], ASan мгновенно прервет тест и покажет точную строку ошибки.

2. Как тестировать динамическую память (malloc / free)

Если вы используете malloc (например, при разборе файла конфигурации erswitcher.conf или динамическом добавлении кастомных правил транслитерации), нужно тестировать две вещи: утечки памяти и отказы выделения памяти.

А. Поиск утечек и порчи памяти (Memory Leaks & Use-After-Free)

Писать отдельные тесты на утечки вручную не нужно — доверьте это автоматике.
• Добавьте в компиляцию тестов флаг LeakSanitizer (в Си он включается автоматически вместе с -fsanitize=address).
• При запуске тестов (локально или в GitHub Actions) при малейшей забытой free() утилита выдаст ошибку и завершит шаг с кодом 1, завалив сборку.

Б. Стресс-тест: Симуляция нехватки памяти (Malloc Injection Fault)

Чтобы проверить, как erswitcher ведет себя, если в системе внезапно закончилась память (например, malloc вернул NULL), можно применить стратегию подмены (Mocking).
В Си это делается элегантно через встроенную возможность линкера ld — флаг --wrap.
1. В коде тестов вы создаете «обертку» над malloc:c
#include <stdlib.h>

int fail_malloc = 0; // Флаг: нужно ли сломать malloc

void* __wrap_malloc(size_t size) {
    if (fail_malloc) return NULL; // Имитируем отказ памяти
    return __real_malloc(size);   // Вызываем настоящий malloc
}
Используйте код с осторожностью.
2. В компиляцию (в Makefile) добавляете флаг -Wl,--wrap=malloc.
3. В тесте Criterion вы пишете:c
fail_malloc = 1; // Включаем режим стресс-теста
int result = parse_config("erswitcher.conf");
cr_assert_eq(result, CONFIG_ERROR_OUT_OF_MEMORY); // Проверяем, что код корректно обработал NULL и не упал в сегфолт
Используйте код с осторожностью.

3. Фаззинг-тесты (Fuzz Testing) — Главный секрет стресс-тестирования

Поскольку erswitcher обрабатывает ввод пользователя (нажатия клавиш) и конфиги, лучшая стратегия стресс-тестирования алгоритмов translit.c — это Фаззинг.
Вместо написания тестов вручную, специальный инструмент libFuzzer (встроен в Clang) будет генерировать миллионы случайных, битых, пустых и гигантских комбинаций байт в секунду, пытаясь «сломать» вашу функцию транслитерации.
Создать такой тест невероятно просто. Создается файл tests/fuzz_translit.c:
c
#include "../src/domain/translit.h"
#include <stdint.h>
#include <stddef.h>

// Эту функцию libFuzzer будет вызывать непрерывно, скармливая случайный мусор в data
int LLVMFuzzerTestOneInput(const uint8_t *data, size_t size) {
    if (size == 0 || size > 1024) return 0;

    // Создаем буфер под результат
    char output[2048];
    
    // Передаем случайный массив байт в вашу функцию транслитерации слова
    translit_string((const char*)data, output, sizeof(output));

    return 0;
}
Используйте код с осторожностью.
Запуск фаззера в терминале:
bash
clang -fsanitize=fuzzer,address src/domain/translit.c tests/fuzz_translit.c -o fuzzer
./fuzzer
Используйте код с осторожностью.
Если в вашей логике работы со строками есть хотя бы малейший шанс выйти за пределы массива при хитрых комбинациях символов, фаззер найдет его за пару секунд, остановится и сохранит файл-сбой на диск.

Итоговый чек-лист стратегии для erswitcher:


Что тестируем	Инструмент / Подход	Где запускаем
Логика перевода (translit)	Модульные тесты (Criterion)	Локально + CI
Статические буферы слов	Граничные тесты (Max + 1 символ) под AddressSanitizer [1]	Локально + CI
Утечки ОЗУ и malloc	LeakSanitizer (флаг -fsanitize=address) [1]	Локально + CI
Отказы системы (malloc == NULL)	Имитация через флаг линкера -Wl,--wrap=malloc	Локально
Стресс на случайный ввод	libFuzzer (Фаззинг входящих строк)
